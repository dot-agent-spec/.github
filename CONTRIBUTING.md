# Contributing

Thanks for your interest in dot-agent. This file is the organization-wide default; an individual
repository may add its own `CONTRIBUTING.md` with project-specific setup that takes precedence.

## Before you start

dot-agent has a lightweight but explicit process. Match the kind of change to the right document:

| You want to… | Do this |
|---|---|
| Propose a new language/protocol feature or a design change | Open an **RFC** (see the governance doc in the spec repo) — design is discussed before code |
| Fix a bug or make a small, already-agreed change | Open a PR directly, linked to an issue |
| Report a bug | Open an issue using the bug template |
| Discuss an idea that isn't a concrete proposal yet | Start a Discussion, not an issue |

The decision process, document types (RFC / ADR / Task), and their lifecycles are described in the
spec repository's `GOVERNANCE.md`. Read it before opening an RFC.

## Pull requests

- Keep PRs focused — one logical change per PR.
- Reference the issue, RFC, or task the PR addresses.
- Match the surrounding code: its conventions, naming, and comment density.
- Make sure the project builds and its checks pass before requesting review.
- Write the PR description so a reviewer understands *why*, not just *what*.

## Commit hygiene

- Write clear, present-tense commit messages ("add X", not "added X").
- Group related changes; avoid mixing refactors with behavior changes.

## Code of conduct

Participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md). By contributing, you agree to
uphold it.

## Licensing

Unless a repository states otherwise, contributions are accepted under that repository's license
(Apache-2.0 for the core projects). Do not submit code you do not have the right to contribute.
